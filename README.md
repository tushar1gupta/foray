# Foray

Marketing site for Foray, an engineering search firm placing early and mid-level
engineers at startups from seed through growth stage.

Live at **https://goforay.io** (Vercel project `goforay`).

Static HTML, no framework, no build step at deploy time. The pages are generated
from Python so the palette and the repeated chrome stay in one place.

## Positioning — read before editing copy

The site presents Foray as a **recruiting agency**. It does not describe an
agent, a product, or automation of any kind. That is a deliberate constraint,
not a style preference:

We do outbound to candidates. A candidate who has just been messaged will look
us up, and until 2026-09-09 what they found was a homepage headlined "Your
autonomous recruiting agent" with an animation of software filling in a Stripe
application — which told them, correctly, that they had been contacted by a
machine. The share card said the same thing, so they did not even need to visit.

So: no "agent", no "autonomous", no automation claims, and nothing that renders
a bot messaging a candidate — including in mockups on the company page, which a
candidate can read just as easily. Sell reach, judgment, and the success fee.

Two things this rule does **not** cover:

- **`src/legal.py`.** The privacy policy and terms describe AI intake calls,
  Retell, and applying on someone's behalf. Those are disclosures about what
  actually happens and they must stay accurate. Do not scrub them to match the
  marketing voice — a bot disclosure deleted while the bot still runs is a worse
  problem than the one this change fixed.
- **`og.png`.** Generated by `configure.py`, and it is what unfurls in iMessage,
  LinkedIn and email previews. It is the whole site to anyone who never clicks,
  so it gets checked whenever the positioning changes.

## Structure

```
index.html          the company page: send us a role  (WAS the candidate page)
candidates.html     engineer intake: introduce yourself
privacy.html        hand-written prose in src/legal.py
terms.html          hand-written prose in src/legal.py
404.html
landing.css         shared, extracted at build time
company.js          index.html's script, extracted at build time
candidate.js        candidates.html's script, extracted at build time
og.png              1200x630 share card, generated
favicon.svg
robots.txt          generated
sitemap.xml         generated
vercel.json         clean URLs, redirects, security headers, asset caching
api/submit.js       the one endpoint: company / engineer / waitlist submissions
db/schema.sql       the submissions table
src/
  landing.py        the shared shell: palette, components, ticker, bar, footer
  company.py        index.html
  candidate.py      candidates.html
  legal.py          privacy and terms prose
  generate.py       builds the HTML
  configure.py      stamps the domain, writes assets, extracts css/js
  check.py          audit: structure, links, copy, forms, JS syntax
  parked/
    candidates.py   the old candidate landing page. Not generated. See below.
```

`landing.py` is named for a page it no longer builds. It is now only the design
system every page shares.

### The parked candidate page

`src/parked/candidates.py` is the "autonomous recruiting agent" landing page
that used to be `index.html`. It is kept, not deleted, and it is not imported by
`generate.py`. Its own CSS travels with it, so `landing.css` ships 25 KB less
than it did.

Reviving it is not just a matter of adding it back to the page table — the file
lists what else changed underneath it. `/companies` and `/engineers` redirect,
so old links still land.

## Build

Requires Python 3.11+, Pillow (for the share card), and Node (for the JS syntax
check only).

```bash
cd src
python3 generate.py                                  # write the HTML
python3 configure.py goforay.io contact@goforay.io   # stamp domain, emit assets
python3 check.py                                     # audit, must report no errors
```

`configure.py` is idempotent. Run it again with a different domain or contact
address and everything downstream updates: canonical tags, Open Graph tags,
`robots.txt` and `sitemap.xml`.

A clean rebuild is byte-identical to the previous one. Nothing depends on the
current time or a random seed at build time.

**Edit `src/`, never the generated HTML.** This has bitten us: the Vercel
analytics tag and the privacy/terms footer links were both added straight to the
HTML and were silently deleted by the next regeneration. Both live in `src/`
now. If you add something to a page by hand, port it or lose it.

## Deploy

Vercel serves the repo root as static files. No build command, no output
directory, framework preset **Other**.

```bash
npx vercel --prod
```

`.vercelignore` keeps `src/` out of the deployment.

## Forms

Both intakes POST to `/api/submit`, which validates against `FORMS` in
`api/submit.js`, inserts into Postgres (`DATABASE_URL`) and emails a
notification via Resend. The field labels in the markup must match the
`required` lists in that file — they are declared in two places and drift
silently.

- **`company`** — from `index.html`. Email, plus either a job link or a
  description (one box decides which by whether it starts with `http`).
- **`engineer`** — from `candidates.html`. Name, email, LinkedIn and what they
  want next are required; phone, GitHub and location are collected but optional,
  because requiring a GitHub loses the infra and ML people who have nothing
  public, and the record is the thing we wanted.
- **`waitlist`** — no page submits this any more. It belonged to the parked
  candidate page. The rows are still in the table.
